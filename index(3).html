4. Configure R1's Three Interfaces

Click:

R1 → CLI

If asked:

Would you like to enter the initial configuration dialog?

enter:

no

Then:

enable
configure terminal

G0/1 — Network 1

interface gigabitEthernet 0/1
ip address 192.168.1.1 255.255.255.0
no shutdown
exit

Why?

This makes R1's Network 1 gateway:

192.168.1.1

G0/2 — Network 2

interface gigabitEthernet 0/2
ip address 192.168.2.1 255.255.255.0
no shutdown
exit

Why?

This becomes the gateway for Network 2.

G0/0 — Network 3

interface gigabitEthernet 0/0
ip address 192.168.3.1 255.255.255.0
no shutdown
exit

Why?

This becomes the gateway for Network 3.

Save:

end
copy running-config startup-config

Press Enter if asked for the destination filename.

6. Configure the DNS Server

Click:

DNS Server → Desktop → IP Configuration

Choose Static.

Enter:

IP Address:       192.168.1.254
Subnet Mask:      255.255.255.0
Default Gateway: 192.168.1.1
DNS Server:       192.168.1.254

Why static?

The DNS Server must always remain at the same address because all clients need to know where the DNS service is.

7. Turn ON DNS

Go:

DNS Server → Services → DNS

Set:

DNS Service: ON

Now add:

Name:     www.dns.com
Address:  192.168.3.253

Click Add.

Why this exact configuration?

A computer normally needs an IP address to reach a server.

We want users to type:

www.dns.com

instead of:

192.168.3.253

Therefore, the DNS Server needs this record:

www.dns.com → 192.168.3.253

192.168.3.253 is the HTTP Server.

DNS does not host the webpage. It only tells the PC where the webpage is located.

So:

DNS Server
192.168.1.254
      │
      │ "www.dns.com = 192.168.3.253"
      ▼
HTTP Server
192.168.3.253

8. Configure the HTTP Server

IP Address:       192.168.3.253
Subnet Mask:      255.255.255.0

DNS Server:       192.168.1.254

Go to:

Services → HTTP

HTTP: ON

9. Configure the DHCP Server

Click:

DHCP Server → Desktop → IP Configuration

Choose Static.

Enter:

IP Address:       192.168.3.254
Subnet Mask:      255.255.255.0
Default Gateway: 192.168.3.1
DNS Server:       192.168.1.254

Why static?

Because R1's DHCP Relay needs to know exactly where the DHCP Server is:

192.168.3.254

10. Turn ON DHCP Service

Go:

DHCP Server → Services → DHCP

Set:

DHCP Service: ON

Do not turn it OFF.

This server will provide DHCP service for Network 2 and Network 3.

11. Create DHCP Pool for Network 2

On the DHCP Server, enter:

Pool Name:        NETWORK2
Default Gateway:  192.168.2.1
DNS Server:       192.168.1.254
Start IP Address: 192.168.2.11
Subnet Mask:      255.255.255.0
Maximum Users:    243

Click Add.

Why?

Network 2 is:

192.168.2.0/24

and its gateway is:

192.168.2.1

We reserve .1–.10, so DHCP starts at:

192.168.2.11

12. Create DHCP Pool for Network 3

Create:

Pool Name:        NETWORK3
Default Gateway:  192.168.3.1
DNS Server:       192.168.1.254
Start IP Address: 192.168.3.11
Subnet Mask:      255.255.255.0
Maximum Users:    242

Click Add.

Why 242?

Available client addresses are:

192.168.3.11
through
192.168.3.252

That's 242 addresses.

We must preserve:

192.168.3.253 = HTTP Server
192.168.3.254 = DHCP Server

13. Configure Router DHCP for Network 1

This is DHCP Method #1 — Router DHCP.

Go:

R1 → CLI

Enter:

enable
configure terminal

Reserve .1–.10:

ip dhcp excluded-address 192.168.1.1 192.168.1.10

Reserve the DNS Server:

ip dhcp excluded-address 192.168.1.254

Now create the DHCP pool:

ip dhcp pool NETWORK1
network 192.168.1.0 255.255.255.0
default-router 192.168.1.1
dns-server 192.168.1.254
exit

Save:

end
copy running-config startup-config

14. Understand the Network 1 Exclusions

This:

ip dhcp excluded-address 192.168.1.1 192.168.1.10

means R1 will not give these addresses to clients:

192.168.1.1
192.168.1.2
192.168.1.3
...
192.168.1.10

Therefore the first possible DHCP address is:

192.168.1.11

And:

ip dhcp excluded-address 192.168.1.254

protects:

192.168.1.254

because it belongs to the DNS Server.

15. Configure DHCP Relay for Network 2

This is DHCP Method #2 — DHCP Relay.

The DHCP Server is on Network 3:

192.168.3.254

But the clients are on Network 2:

192.168.2.0/24

DHCP broadcasts normally cannot cross a router.

Therefore, R1 needs a helper address.

Go to:

R1 → CLI

enable
configure terminal

Then:

interface gigabitEthernet 0/2
ip helper-address 192.168.3.254
exit

Save:

end
copy running-config startup-config

Why G0/2?

Because:

R1 G0/2
     ↓
Network 2
192.168.2.0/24

The helper tells R1:

"Forward DHCP requests received from Network 2 to the DHCP Server at 192.168.3.254."

16. Why the Helper Address Is Necessary

Without the helper:

PC2
 ↓
DHCP Broadcast
 ↓
S2
 ↓
R1
 ✖

The router does not normally forward the DHCP broadcast.

With:

ip helper-address 192.168.3.254

it becomes:

PC2
 ↓
S2
 ↓
R1 G0/2
 ↓
DHCP Relay
 ↓
192.168.3.254
 ↓
DHCP Server

The DHCP Server then uses the:

NETWORK2

pool and gives PC2 an address such as:

192.168.2.11

17. Do NOT Add Helper Addresses Everywhere

You only need:

interface gigabitEthernet 0/2
ip helper-address 192.168.3.254

You do not need it on G0/1 because R1 itself provides DHCP for Network 1.

You do not need it on G0/0 because the DHCP Server is directly connected to Network 3.

The three DHCP methods you should be able to explain

1. Router DHCP

R1 directly assigns IP addresses to Network 1 clients.

2. DHCP Relay

R1 forwards DHCP requests from Network 2 to the dedicated DHCP Server on Network 3 using ip helper-address 192.168.3.254.

3. Dedicated DHCP Server

The dedicated DHCP Server directly serves Network 3 and also provides the DHCP pool used by Network 2 through the relay.

And importantly, you leave the DHCP service ON. You are not switching DHCP methods globally; you're demonstrating different DHCP methods on different networks at the same time.
